# 3D 장난감 캐릭터 릴스: 화면 특징별 three.js 가능 여부 (2026-11-17)

대상: @canwebuildthis 같은 '책상 위 점토·장난감 3D 캐릭터 시트콤' 화면. 형식만 보고, 그 계정의 캐릭터·시리즈 이름·개그는 쓰지 않는다.
우리 캐릭터: 회사 로고의 모티프와 브랜드 색을 본떠 코드로 직접 만든 3D 모델 (클로드 = 주황 햇살 머리 점토 인형, 제미나이 = 파랑→보라 4갈래 반짝이 별, 챗GPT = 고리 6개 매듭 꽃 흰 점토). 글자 로고·평면 로고 없음, 화면에 '비공식 팬 캐릭터'.
시제품: `experiments/threejs-test/` — v2 = 슬라임 진행자(`scene.js`, 7초), v3 = 사람 주인공 '나'(20대 여성 직장인, `scene3.js`, 7.5초, 슬라임 없음). 1080x1920 30fps, ElevenLabs 대사 1줄. 측정은 이 노트북(Intel Iris Xe).

판정 기호: ◎ 지금 바로 블렌더급 / ○ 가능, 블렌더보다 조금 모자람 / △ 흉내만 / ✕ 어려움

30초 릴스(900프레임)로 바꾸면:
| 방법 | 30초 릴스 |
|---|---|
| A. 이 노트북 GPU (매일 작업이 어차피 이 컴퓨터에서 돎) | v3 약 50초, v2 약 1분 |
| B. Actions 1개, SwiftShader, 전부 켬 | v3 약 45분, v2 약 67분 |
| C. Actions 1개, 720p (보케 유지) | v3 약 27분 |
| D. Actions 행렬 10개로 프레임 나눔 (`actions-matrix.example.yml`, `--range`·`--encode-only`) | v3 전부 켬: 작업당 90프레임 ≈ 4.5분 + 설치 1~2분 + 합치기 1분 ≈ 8분 |
| E. D + 720p | 약 5분 |
러너 속도는 이 노트북 SwiftShader와 같다고 가정(공개 저장소 ubuntu 러너 4코어, 실제로는 1~1.5배 느릴 수 있음). 공개 저장소라 분 사용량은 무료, 동시 작업 20개. 실제 러너 시험은 .github/workflows에 파일을 넣어야 해서 이번엔 하지 않았다(예시 파일만).
비교: 블렌더 Cycles 같은 장면은 프레임당 20~60초 추정(30초 릴스 5~15시간), EEVEE는 1~3초(15~45분)이고 GPU 없는 러너에선 더 느림.

## 블렌더와 비교한 결론
- 캐릭터 연기·카메라·자막·대사 맞춤은 three.js 쪽이 더 낫다 (코드라서 대사 시각에 프레임 단위로 맞추고, 매번 새 대본으로 자동 생성).
- 모자란 것은 '재질과 빛의 깊이': 진짜 GI, 카우스틱 있는 젤리, 한 덩어리로 빚은 점토·머리카락 모델. 모델만 블렌더에서 한 번 만들어 glTF로 가져오면(혼합안) 모델 문제는 사라지고, 빛은 라이트맵 굽기 또는 SSAO로 대부분 메운다.
- 렌더는 이 노트북 GPU가 기본(30초 릴스 1분 안), GitHub Actions는 행렬 분할(8분 안팎)을 예비로.
